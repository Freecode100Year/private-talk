Core Principles

Four Core Principles

No accounts, no friction. Privacy by technical design, not by promises.

Quick Start

In 30 Seconds

Three simple steps to start a secure conversation anytime, anywhere.

1

Enter with your passphrase

Open https://chat.freedom8964.com/#your-passphrase. Opening the home page directly generates a random passphrase nobody can guess.

2

Share the address with friends

Send the address or the agreed passphrase to your friends. Links do not expire, and the passphrase is wiped from the address bar upon entry.

3

Chat freely, then close the tab

Everyone opening the same address joins the same room (up to 25 people). The host can lock the room. When everyone leaves, the room vanishes.

Passphrase Advice: A passphrase may use letters and digits of any language, without symbols. The longer, the safer. See the User Manual.

🔐 End-to-End Encryption & PFS

End-to-End Encryption: Keys come from the passphrase in the browser (PBKDF2 310,000 rounds → HKDF → AES-256-GCM). Messages are padded to fixed sizes before encryption so ciphertexts do not reveal length.

Forward Secrecy & Post-Quantum: Every participant creates an ephemeral key pair; every message uses a one-time key; when someone leaves, everyone rotates keys. Pairwise keys integrate ML-KEM-768 against future quantum decryption. Each message is signed, preventing seat impersonation, and a 20-digit safety code allows verification in person or by phone.

Nothing Kept, Few Traces: No accounts, no message history, no server logs. The room disappears when empty. No cookies, no local storage, caching is disabled, and the browser is instructed to clear site data upon closing.

🛡️ Tamper-Proof & Access Control

Encrypted Pictures: Compressed in browser, stripping GPS location and camera EXIF metadata, encrypted with one-time keys inside forward-secret frames.

Tamper Resistance & Host Control: Sender id, timestamp and counter are sealed inside ciphertext; the earliest entrant is the host, who can lock the room or remove disruptive participants.

No Passphrase, No Entry: The server requires an access hash derived from the passphrase; knowing the room address alone cannot seat a connection, lock the room, or post. The passphrase is in the URL hash fragment and is never transmitted over the network.

⚠️ What It Cannot Do (Please read carefully)

  • Anyone with the passphrase can enter and read subsequent messages. Short passphrases can be guessed; use random passphrases for anything sensitive. Invitation links do not expire. Rooms with older client versions will fall back to legacy encryption without forward secrecy (the page displays a notification).
  • The server sees IP addresses. To hide your IP address, use a VPN you trust or Tor.
  • It cannot prove who is in the room; other participants can take screenshots, take photos, or copy text. Third-party keyboards and compromised devices are beyond what any web page can protect. "Clear screen" only clears your own display.
  • The web page is delivered by the server: If the operator's account is compromised, the page code could be modified. A signed integrity manifest catches global modifications, but targeted attacks require the Android App or offline packages where code is pre-packaged locally.
For full security analysis, see Privacy & Security Design (docs/privacy.md).

Each deployed site serves a signed integrity manifest (dist/integrity.json). You can verify any running instance against its cryptographic release signature: 

node scripts/verify-site.mjs https://chat.freedom8964.com

✍️ Package Signatures & Hashes

Every offline and Docker package in a release comes with SHA-256 checksums and a signature by the release key (public key: server/release-key.pem); the updater refuses a package whose signature does not match. Android APK checksums are on their release pages.
