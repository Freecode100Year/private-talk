# 掼蛋与麻将首版设计

用户授权自行决定并实现。公开桌优先，现有文字翻译与隐私要求继续有效。

## 选择与范围

复用现有公开桌及服务端裁判。客户端裁判会泄露暗牌；加密联合洗牌的复杂度不适合本轮，因此选择服务端保存对局必需状态并分别投影给玩家，聊天仍走原有加密通道。不增加账号、统计、长期战绩或外部服务。

掼蛋：四人，两个对家组成搭档，108 张牌、每人 27 张；支持主级牌、红桃级牌配牌、基本牌型与炸弹比较、接风、升级、下一副的进贡还贡。首版必须在规则界面列出具体采用的规则，不能声称覆盖所有竞赛变体。

麻将：四人，万筒条 108 张，无字牌花牌；先定缺，不允许吃，支持碰、明杠暗杠补杠、摸打与胡牌、多家同时胡、胡后退出当前手并继续至三人胡或牌墙耗尽。明确命名“麻将·血战入门”；不换三张，不计杠分、不查叫/查花猪，按界面公开的基础胡牌计分，仅计当前局分数。后续再扩展完整地方规则，避免首版冒称标准四川规则。

两种游戏均为固定四人公开模式。私密房间暂不接入，避免改变原有“服务器不见私密游戏状态”的承诺。公开房聊天不向游戏规则引擎传递明文。

## 引擎接口

文件 `src/guandan.js` 导出 `GuandanJudge`；`src/mahjong.js` 导出 `MahjongJudge`。
统一接口：constructor(saved=null)、start(players,now)、handle(n,action,now)、tick(now)、members(list,now)、view(n)、toJSON()；getter on、deadline、game。
输出为 `[{to:n,msg:{type:'cards',game:'gd'|'mj',state:view(n)}}]`，不得广播完整牌局。
view 包含 type、gid、revision、phase、players、turn、deadline、hand、counts、scores、合法动作信息，以及各玩法公开牌面；没有牌权者 hand 为空。牌为唯一整数 ID，不能只按点数标识两张相同的牌。
每个行动必须包含 gid、revision 和 k，拒绝旧局、重复、越权、伪造手牌。动作只经 `ref` 通道，由当前连接座位决定发起人。重连只向原座位投影手牌；未开始下一局前，结算快照可保留在当前房间，房间空时全部删除。

## 接入与可用性

Node 与 Cloudflare 使用同一个引擎和消息路由规则。公开桌四人到齐自动开始；游戏切换不能覆盖正在运行的裁判。断线座位保留现有短重连窗口，回归时同步当前状态；回合超时提供确定性合法行动或停局说明。Node 重启不承诺恢复对局。

牌桌用独立 DOM 渲染模块，不继续将玩法细节堆入 app.js。手机手牌可换行/横向滚动，点选后再确认，清楚显示轮到谁、上一手/弃牌、行动结果和规则。使用项目本地 CSS 与符号，不引入外部牌图或 SDK。

## 验收

规则单元测试、完整自动对局、畸形/重复/越权事件、秘密投影、序列化恢复、断线重连、手机真实点击；两后端 smoke 与既有完整 CI。未通过不得部署。发布要求现有签名链、同一源码版本、两站各自验证与回退；无权限或测试失败明确报告。
