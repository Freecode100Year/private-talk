# Private Talk 游戏平台：分析与设计（第一步）

分支：`feat/game-platform`。本文只做分析和设计，没有改任何运行中的代码。
依据：2.18.0 的代码（`dist/`、`src/`、`server/`、测试），以及线上站点的实际画面：桌面 1366×860、手机 390×844 的 Chromium 截图，在本目录 `now-*.webp`；另外此前在安卓 11 的 WebView 83 上实测过。

---

## 0. 结论先说

1. **能渐进做，不用重写**。
   - 六个游戏（五个已上线，骗子骰在 `feat/liars-dice` 分支）的规则模块本来就是纯函数：`apply(state, event, from, now)` 加 `dealerMove`。
   - 这正好是「游戏内核」需要的形状，内核可以包在它们外面。
2. **任务书里有一条和端到端加密冲突，需要你拍板：可信裁判**。
   - 「不要把浏览器当可信裁判」和「服务器看不到内容」不能同时完全成立。
   - 我的建议是分两种桌子：
     - **私密房间（现在的模式）**：服务器继续什么都看不到。规则由每个浏览器各自校验，能做到的都用「承诺—揭示」和联合随机数去掉「庄家知道一切」。
     - **公开桌（新）**：给陌生人快速开局用。服务器当裁判，保管暗牌，**服务器能看到牌局，但看不到聊天**。界面上明确标出这一点。
3. **「快速玩游戏 / 全局大厅」需要服务器新增「公开桌列表」**。
   - 只登记玩家主动设成公开的桌子。私密房间永远不进列表，也无法被枚举。
   - 公开桌的暗号等于公开，任何人都能进，这一点要在界面上直说。
4. **第三方游戏 SDK 必须用沙箱 iframe 运行**。
   - 否则第三方代码和聊天在同一个页面里，能读到密钥和聊天内容。

## 3. 游戏内核模块规划

内核放在 `dist/core/`，现有游戏的规则文件不动，外面加一层适配。每个模块都是纯 JS、无框架，兼容 Chrome 83。游戏代码用 `import()` **按需加载**：只聊天的人不下载游戏。

| 模块 | 职责 | 复用的现有代码 |
|---|---|---|
| `registry` | 游戏清单：id、名称键、人数、时长、支持的信任模式（私密 / 公开）、设置项、规则文本、`load()` | 现有的 `MIN_PLAYERS/MAX_PLAYERS`、`RULES`、`game.name.*` |
| `table` | 桌子生命周期：组桌 → 入座 / 准备 → 进行 → 结束 → 再来一局；座位、临时昵称、头像；离桌、补位、重开投票 | `gameRoom()`、busy / free 一房一局 |
| `referee` | 跑规则：同一份 `apply` 在每个页面（私密）或服务器（公开）上跑；不合法的事件一律丢弃；事件顺序由中继决定 | 六个游戏的 `apply`（已经是纯函数） |
| `coordinator` | 计时和推进：`dealerMove`。**接替机制**：协调者离开时，在座编号最小的页面接手（只限不需要暗牌的步骤）；需要暗牌的游戏转为「暂停 → 补位或作废」 | 各游戏的 `dealerMove` |
| `secrets` | 只给本人看的信息：给某一个座位加密（`sealFor`）、承诺—揭示、联合随机数、洗牌（见第 4.2 节） | `group.sealFor/openFrom`、交易所 / 骗子骰的承诺代码 |
| `sync` | 断线恢复：重连的页面向在座的人要「状态快照」（公开状态 + 哈希）；至少两个在座页面给出相同哈希才采用；本人的暗牌由持有者（庄家 / 服务器）重新加密发给他 | 新增 |
| `votes` | 通用投票：补位（≥80% 在座且在线者同意）、重开、再来一局、踢出挂机 | 狼人杀投票的界面部分 |
| `express` | 快捷表达：👍😂🤔😱🙏 等固定表情，限频，走游戏事件通道 | 发送额度机制 |
| `transport` | 私密：沿用消息信封里的 `g` 字段（加密、签名、限频）；公开桌：另一条到服务器裁判的通道 | 现有 |
| `sdk` | 第三方游戏的接口：`defineGame({ meta, setup, apply, view, timers })`；在沙箱 iframe 里运行，只能用 `postMessage` 收发事件 | 新增 |

**SDK 的安全边界**：第三方游戏 = `<iframe sandbox="allow-scripts">`，不加 `allow-same-origin`。它拿不到密钥、聊天、Cookie，也不能联网（CSP 设 `connect-src 'none'`）。它只能收到「本游戏的事件」和「发给本座位的暗牌明文」，只能提交「本游戏的动作」。

**和现有功能的兼容**：先做 P1（见第 6 节），把六个游戏挂到 registry 上，行为完全不变，现有 16 套浏览器测试必须原样通过，再动界面。

## 4. 安全风险说明

### 4.1 「浏览器当裁判」现在到底信任了什么

| 风险 | 现状 | 评估 |
|---|---|---|
| 改过的客户端发非法动作（不是自己的回合、超出规则） | 每个页面都用同一份纯函数规则校验，非法事件被所有诚实页面丢弃；事件全局有序（同一个中继） | **已防住**：等同于「多副本校验」 |
| 冒充别人发动作 | 每条消息带发送者签名，编号无法冒用 | **已防住** |
| 只有协调者能叫超时 / 中止 | 协调者可以拖延或中止，也可以离开让游戏作废 | 中等。方案：协调者接替 + 「重开 / 中止」改为在座者投票 |
| **庄家知道全部暗牌** | 暗号潜伏（谁是卧底、两个词）、密电逃脱（密码）、狼人杀（全部身份）：开局者的页面内存里有 | **高（公平性）**，见 4.2 |
| 已经去掉庄家的 | 密约交易所、秘密任务、骗子骰：承诺—揭示 + 联合随机数，开局者也看不到 | 安全 |
| 流量侧信道 | 狼人杀夜里人人都发一条（真的或空的）；其余游戏的公开动作本来就公开 | 安全 |

### 4.2 暗号潜伏的庄家问题和改进方案

**现状**：开局者的页面决定词对、哪个词是多数、谁是卧底。投票也加密交给它计票。它的页面内存里有全部信息，改过的客户端或懂行的人看一眼就作弊。

**方案 A：无庄家洗牌（推荐用于私密房间）**
- 做法：用可交换加密的「心理扑克」（SRA，浏览器原生 BigInt 做模幂运算）。
  1. 开局者生成 n 张身份牌（n−1 张「平民词」、1 张「卧底词」，两个词都先加密）。
  2. 每个人依次用自己的密钥加密整副牌并打乱。
  3. 每张牌发给一个座位，其他人逐个去掉自己那层加密，只有拿牌的人能解开最后一层。
- 效果：**谁也不知道卧底是谁，开局者也不知道**。开局者仍然知道两个词和哪个是少数，所以他知道自己是哪边（比现在知道全部要好得多）。
- 代价：
  - 每人多发约 2 条消息，按发送额度大约多 10–20 秒开局时间。
  - 2048 位模幂，旧手机每张牌约几十毫秒，可以接受。
  - 计票改成承诺—揭示：投完一起亮，不需要庄家。
- 不碰聊天加密：这些都走现有的游戏事件通道，在端到端加密里面。

**方案 B：不玩的庄家**：开局者只当庄家不参加，适合线下聚会。用户之前说过「法官没有游戏体验」，只作为可选项。

**方案 C：服务器当庄家（只用于公开桌）**：见 4.3。

**狼人杀**：自动法官必须知道身份才能结算夜晚。完全去掉庄家要用安全多方计算，太重，不做。私密房间维持现状并继续明示；公开桌用服务器法官。

**密电逃脱**：合作游戏，庄家知道密码等于自己能解，影响小。私密房间维持现状；公开桌由服务器出题。

### 4.3 公开桌与大厅（新）

| 风险 | 设计 |
|---|---|
| 私密房间被列出或枚举 | 大厅只收「主动登记」的公开桌。房间 id 仍是暗号的哈希，服务器不保存暗号；私密房间的代码路径里根本没有登记接口 |
| 公开桌的暗号 | 等于公开（大厅会发给任何点「加入」的人）。界面明说：「公开桌：任何人都能进，服务器能看到牌局，聊天仍加密传输，但桌上的人都能看到」 |
| 服务器当裁判 | 只看到公开桌的牌局（身份、骰子……），看不到私密房间的任何东西。暗牌只在 Durable Object（或 Node 进程）内存里，对局结束即丢弃，不写盘、不进日志 |
| 大厅泄露的元数据 | 只公开：游戏、人数 / 座位、语言、创建时间、是否有人等。没有 IP、昵称、聊天 |
| 刷桌子 / 占坑 | 按「项目不设审查」的原则，只按数量和频率限制：每个地址同时最多 2 张公开桌；没人加入的桌子 10 分钟自动消失；没有关键词过滤 |
| 自托管和离线版 | 大厅只列本服务器上的公开桌，离线局域网版同样适用；一键部署版默认可以关掉大厅 |

### 4.4 其他新增功能的风险
- **临时昵称**：只是装饰，可以重名、可以冒充，身份锚点仍然是座位号和签名。昵称在加密消息里传，服务器看不到，不保存。
- **补位（80%）**：补位者拿到的是空出来的座位。暗牌：
  - 有庄家 / 服务器的游戏，重新加密发给补位者。
  - 承诺—揭示的游戏，这个座位本轮的暗牌作废（例如骗子骰本轮不参与）。
  - 防刷：投票人只算「在座且在线」的人。同一个人开多个页面能多投票，这和现在占座位的问题一样，无法从技术上杜绝，界面会显示人数。
- **断线快照**：只在至少两个在座页面给出相同哈希时才采用，防止一个人伪造快照。
- **快捷表情**：只能从固定列表里选，限频，不提供自由文字通道，绕不开现有的限频。
- **资源**：游戏代码按需加载；不加框架；动画只用 CSS `transform` 和 `opacity`；继续兼容 Chrome 83（`test/compat.test.mjs` 强制检查）。

## 8. 2.21 游戏内核实现说明

在 2.21 版本中已落地四项核心机制：

1. **协调者接替（dealerStep 交接）**：
   - **纯公开状态游戏**（暗号潜伏、骗子骰、交易所、秘密任务）：开局者离开房间超过 8 秒后，由留在场内的、`game.players` 中号码最小的玩家接替履行协调职责（驱动计时、跳过离线者、推进回合）。规则统一抽取为纯函数 `coordinator(s, here)`（见 `dist/coord.js`），各游戏 `apply` 方法验证管理事件发自当前协调者。
   - **含私密信息游戏**（密电逃脱、私密房间狼人杀）：开局者持有关键秘密（题底或角色身份），无法接替。开局者离开超过 8 秒后，所有玩家页面本地结束对局，提示「开局者离开了，这局无法继续（谜底/身份只在他的页面里）」，并释放房间 busy 锁，使面板回到可开新局状态。
   - **一房一局配合**：协调者变更及对局重置后，`busyGame` 状态同步更新或解开，不阻塞新局。

2. **再来一局（Play Again）**：
   - 对局结束（`phase === 'over'`）后，面板提供「再来一局」按钮，沿用相同游戏类型与前次配置（如狼人杀板子与警长规则、骗子骰万能 1 点规则），对齐所有已有开局校验规则。
   - **公开桌自动续局**：非狼人杀公开桌对局结束后保留 15 秒展示结果与倒计时，满座自动开始下一局；服务器裁判的公开狼人杀同样在结算后等待 15 秒（Worker 端借由 alarm 定时）自动发牌续局。

3. **快捷表情（Quick Reactions）**：
   - 游戏面板常设 6 种快捷表情（👍 😂 😮 😡 🤔 👏），通过端对端加密消息管道发送（信封增加 `q: 0–5`，正文为空），页面端设 3 秒防刷限流。
   - 收到表情后以紧凑系统小字（如「#3 👏」）插入聊天区，并在对应成员列表及座位头像旁浮动弹出气泡，展示 3 秒后淡出。

4. **手机房间分页与座位条（Mobile Tabs & Seat Bar）**：
   - 屏幕宽度 ≤600px 时在顶部引入「聊天 / 游戏 / 房间」三标签切换。对局开始时自动切至游戏页；游戏页处于后台且有新聊天时，聊天标签高亮显示未读角标。
   - 面板顶部加入统一座位条，借由 `seatsOf(game)` 统一抽取出入局、当前轮到行动者（发光边框）、离开（虚线）以及表情气泡等统一状态显示。

## 9. 2.21 第二部分实现：玩法目录与房间内换游戏

1. **玩法目录统一抽象（`dist/modes.js`）**：
   - 将所有游戏板子与玩法平铺为标准数据结构 `{ id, game, players: [min, max], settings, public, group, board }`。
   - 狼人杀 23 个板子全部成为独立玩法，分为入门（6–8 人）、标准（9–11 人）、12 人进阶与特殊模式，由板子配置自动生成身份构成描述。
   - 提供骗子骰（经典 / 1 点万能）、暗号潜伏、密约交易所、秘密任务和密电逃脱（私密房间）等玩法。

2. **首页「快速找一桌」改版（平铺横幅卡片）**：
   - 摒弃以往「几人桌」下拉框与两步操作，直接平铺通栏横幅渐变卡片。
   - 按钮上直观标注「坐下 · 已有 3/9」或「开新桌」，点击直接完成动作。
   - 狼人杀设计两层直观交互：第一层按人数（6–12 人局），若该人数有多个板子则展开第二层板子卡片，单个板子则直达。

3. **公开桌暗号与人数可变开局**：
   - 公开桌暗号采用 `pub<modeId>-<16rand>` 新格式，完全向下兼容旧版。
   - 人数可变玩法（如骗子骰 2–8 人）在在场人数达到最低人数后，出现「准备」按钮；全员准备、坐满或 45 秒倒计时结束即自动开局（新人进入倒计时重置）。

4. **房间内选游戏与 80% 换游戏表决**：
   - 房间侧栏统一为选游戏横幅卡片列表，自动把当前在场人数可玩的玩法置前，人数不足的置灰并标注“还差 N 人”，无对局时点卡片直接开局。
   - 局内点其他玩法卡片即发起「提议换成该游戏」，也可提议提前结束本局。发起加密游戏事件发起 30 秒表决，在场玩家 ≥80%（向上取整）同意即结束当前局并开启新玩法；不够 80% 或超时作废，同人 60 秒内防刷冷却。
   - 公开桌表决通过后，房主通过 `{ type: 'table', mode }` 帧向服务器同步新玩法，大厅列表与裁判生命周期（切换至/出狼人杀法官）自动同步。
