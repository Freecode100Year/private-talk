# 隐私与安全设计

[README](../README.md) 里是简要版。这里逐项写清楚每一层怎么做、能防什么、防不了什么。适用于 2.0 及以后的版本。

## 一句话

无需账号；消息在浏览器里加密；本项目的转发程序不保存聊天消息、不写日志。**但**服务器能看到连接信息，参与者能自行保存内容，网页代码和设备本身仍需要可信。

## 谁能看到什么

| | 服务器运营方 | 网络上的旁观者（运营商、Wi-Fi 管理者） | 房间里的其他人 |
| :--- | :--- | :--- | :--- |
| 消息内容 | 看不到（只有密文） | 看不到（HTTPS + 端对端加密） | 看得到，也能截图、复制 |
| 暗号 | 看不到（只在浏览器里用） | 看不到 | 知道 |
| 你是谁 | 不知道（无账号、无昵称） | 不知道 | 只看到编号 1️⃣～🔟、#11～#25 |
| 你的 IP 和上线时间 | 看得到 | 看得到你连了这个网站 | 看不到 |
| 哪些连接在同一个房间、消息的长度和时间 | 看得到 | 看不到 | 看得到 |
| 同一个暗号以后又被打开 | 看得到（房间地址相同） | 看不到 | — |

## 密钥与房间

| | 做法 |
| :--- | :--- |
| 暗号 | 默认随机生成 22 个字符（约 128 位随机性）。放在链接 `#` 后面，浏览器不会把它发给服务器；进入房间后立即从地址栏抹掉；页面只显示 4 位房间代号，截图不会泄露暗号 |
| 派生 | 暗号经 PBKDF2-SHA256（31 万次）得到主密钥，再用 HKDF 分出两样互不相关的东西：**进入凭证**和**消息密钥** |
| 房间地址 | 进入凭证的 SHA-256。服务器知道地址，但由地址算不出进入凭证，更算不出暗号和消息密钥 |
| 进入 | 连接时浏览器出示进入凭证（放在 WebSocket 子协议头里，不在网址里），服务器核对它的 SHA-256 等于房间地址才放行。**只知道房间地址的人（例如从日志里看到）进不来**：不能占座、不能锁房、不能发消息 |
| 消息 | AES-256-GCM，每条消息随机 12 字节 IV。消息密钥从不离开浏览器，服务器只转发密文；快捷表情也是端对端加密消息（走现有加密通道与额度，正文为空，带 q 字段） |
| 长度 | 加密前把每条消息补齐到 256 / 512 / 1024 / 2048 / 4096 字节中最近的一档（ISO/IEC 7816-4 填充），服务器和网络旁观者只能看出大概档位，看不出一句话多长 |
| 防篡改 | 发送人编号、消息编号、发送时间都封在密文里。浏览器核对服务器标注的发送人，拒绝本页已见过的消息编号，并**按本机时间**拒绝相差 10 分钟以上的消息（服务器报的时间只用来提醒本机时间不准，不参与判断） |
| 前向保密（2.4 起，协议 v3；2.7 起 v3.1） | 每个人进房时在浏览器里生成两对临时密钥（P-256）：一把 ECDSA **签名密钥**，整个访问期间不变；一把 ECDH 密钥，每次换钥时都换新的。公钥连同签名用消息密钥封好后发给房间，服务器既看不懂也伪造不了。两两之间由 ECDH + HKDF（以暗号派生的值作盐）得到配对密钥，每人用它把自己的**发送链**交给其他人。每条消息用发送链往前走一步得到的一次性密钥加密（HMAC-SHA256 链），用过的那一步立即丢弃。有人离开、掉线或被移出时，以及每发 100 条或每 10 分钟，都会换一条新的发送链和新的 ECDH 密钥，只交给还在的人。临时密钥只在网页内存里，离开就没了：**事后拿到暗号，也解不开当时录下的密文**。实现见 `dist/group.js` |
| 抗量子（2.8 起，协议 v3.2） | 每人进房时另生成一对 ML-KEM-768 密钥（FIPS 203 标准的后量子算法），公钥连同签名发给房间。每两个 2.8 成员之间，编号小的一方用对方的公钥封装一个随机秘密，随第一次交出的发送链一起发过去；之后两人的配对密钥由 ECDH 结果**和**这个秘密一起经 HKDF 算出。防的是「先录下来，以后再解」：有人现在录下服务器上的密文，以后拿到暗号、又有了量子计算机，单靠 ECDH 的密钥能被算出来，加上 ML-KEM 就不行。这是**混合**方案：ML-KEM 用的是 noble-post-quantum 库（`dist/vendor/mlkem.js`，与 OpenSSL 的实现交叉验证过，但没有独立审计），所以只叠加在 ECDH 上，不单独使用，两者都被攻破才会失效。ML-KEM 密钥整个访问期间不变，离开就丢弃。房间里有 2.7 的成员时，和他们之间不用 ML-KEM（侧栏会说明），其余成员之间照用；全体都是 2.8 时侧栏显示「⚛️ 抗量子」 |
| 签名 | 2.7 起每条消息都用发送者的签名密钥签名。房间里每个人都持有别人的发送链，没有签名的话，一个成员和服务器串通就能冒用别人的编号发言；有了签名，冒用会被识破，消息不显示 |
| 安全码 | 侧栏里的 20 位数字（约 66 位强度），由每个人的签名公钥算出。通过电话或当面核对一致，就说明没有人被调包。2.4–2.6 的 6 位码太短：攻击者换几十万次密钥就能凑出相同的码。点「我已核对安全码」后侧栏显示 ✅；有人进出或密钥变化，核对自动作废。同一编号没有离开却换了签名密钥，会醒目提示可能有人冒充 |
| 严格模式（默认） | 只收发有前向保密和签名的 v3.1 消息。房间里有旧版本的成员（2.3 及以前没有 v3，2.4–2.6 没有签名），或服务器是旧版本时，**暂停收发**并说明是谁；旧版本发来的消息不显示。每个人可以在侧栏勾选「允许旧版本」，只对这次访问有效，之后与旧版本之间的消息没有签名、可能也没有前向保密。服务器故意丢掉密钥消息，最多只能让房间暂停，不能悄悄降级 |
| 丢消息 | v3 消息带每人自己的序号，中间有消息没送到（断网或被服务器丢弃），收到下一条时会提示少了几条。收到用还没拿到的钥匙加密的消息（密钥公告丢了或晚到），先暂存最多 30 秒，向对方要钥匙后补读；为此，发出去的链位置保留 60 秒，最近几把 ECDH 密钥也保留 60 秒，这是前向保密上的小小让步 |
| 房间代号 | 4 位十六进制，约 16 位，只用来发现暗号输错，**不是安全验证码** |

## 房间与成员

| | 做法 |
| :--- | :--- |
| 身份 | 无账号、无昵称，按进入顺序编号 1️⃣～🔟，第 11 位起是 #11～#25。先发没用过的编号，25 个都用过后再发最早空出的那个。编号只是座位号，不能证明对方是谁 |
| 房主 | 连续在房间里最久的人是房主（👑），由服务器按进入顺序判定。**只有房主**能锁定 / 解锁、移出成员；房主离开或掉线后，下一位最早进入的人自动接任；掉线回来的人排到最后 |
| 锁定 | 锁定后新的人进不来；掉线的人凭重连凭证 2 分钟内能回来 |
| 移出 | 房主移出某人：服务器断开他，并作废他的重连凭证。房间锁定时他回不来；没锁时他拿着链接仍能作为新成员进来，所以要先锁再移出 |
| 断线 | 每 25 秒心跳，无响应或断开就自动重连；掉线 2 分钟内凭重连凭证回来仍是原编号。**所有人都断开时**（例如大家同时锁屏），房间状态（编号、锁定、重连凭证）随之消失，再连上就是重新开始的房间，页面会提示编号已变、锁定已解除 |
| 历史 | 不存储。新加入的人看不到之前的消息；断线期间的消息收不到 |

## 网页与浏览器

| | 做法 |
| :--- | :--- |
| 网页 | 无外部资源、无统计、无 Cookie；CSP 只允许本站资源；不发送 Referer；禁止被其他网站嵌入；HSTS |
| 本地痕迹 | 不用 Cookie、localStorage 等浏览器存储；所有响应 `Cache-Control: no-store`；打开、切到后台、关闭页面时请求 `/bye`，服务器回 `Clear-Site-Data: "cache", "storage"`；`NEL: {"max_age":0}` 关闭网络错误上报；离开时丢掉暗号、密钥和消息的引用；输入框关闭拼写检查 |
| 清屏 | 「清屏」和「本机自动清屏」只清**你自己这台设备**的屏幕，不影响别人，也删不掉别人保存的内容 |
| 游戏「暗号潜伏」（2.10 起；2.20 起没有庄家） | 游戏的每一步都是普通消息，和聊天一样加密、签名、限速。2.20 起**没有人知道全部的牌**：开局的人写好牌（n−1 张同一个词、1 张潜伏者的词）后，所有人的页面依次用自己的密钥加密整副牌并打乱，再依次去掉自己那一层（只留牌主人的一层），每人只能读出自己的牌（SRA 交换加密，1536 位安全素数，`dist/sra.js`）。开局的人知道两个词，所以知道自己是哪边，但不知道谁是潜伏者。每张牌带随机填充、取平方数，相同的牌看起来也不一样。投票先发 SHA-256 承诺、全员投完再一起亮出，每个页面自己计票。出局的人公开自己的解密密钥，别人用它解开他的牌来核对，伪造一张别的有效牌相当于解离散对数。开局者的页面只负责叫时间。限制：一个改过的页面在洗牌时可以复制或丢掉牌（例如造出两个潜伏者），结束时大家亮牌能看出不对，但查不出是谁。什么都不保存
| 游戏「密电逃脱」（2.11 起） | 和暗号潜伏一样：每一步都是普通消息，每人的线索只为他一个人加密。试的密码是公开给房间里所有人的（大家本来就是一队）。开局的人的浏览器出题和判定对错，所以**它知道全部密码**。有人离开时，开局的人的浏览器会把他的线索公开给房间里的人，好让大家还能解开。什么都不保存 |
| 游戏「密约交易所」（2.12 起） | 每人的选择先只发出一个哈希承诺（SHA-256，含随机盐），等配对的人都锁定后才一起亮出，每个页面自己核对哈希，所以**包括开局者在内谁也不能提前知道别人的选择**，也不能事后改。纸条只为收件人一个人加密（两人之间的 ML-KEM 秘密）；房间里其他人只看得到「谁给谁递了纸条」，看不到内容。下一轮的配对由大家亮出的随机盐算出，开局者只负责第一轮配对和超时。什么都不保存 |
| 游戏「秘密任务」（2.13 起） | 每人的任务（目标是谁、要对方说的词）由**自己的页面**随机抽取，只发出哈希承诺（SHA-256，含随机盐），**包括开局者在内谁也不知道别人的任务**。完成时页面公开这个任务和那条消息的编号，每个页面用自己收到的消息核对：确实是目标本人在任务开始后说的、确实含这个词、和承诺一致。被人猜词时由被猜的页面自动如实回答；被改过的页面若否认了猜对的词，之后公开任务时会被发现并扣分。聊天内容只在各自的浏览器里比对，不发给任何人。什么都不保存 |
| 游戏「狼人杀」（2.15 起） | 法官由程序自动担任，**人人都拿身份**（2.15.1 起，开局者也一样）。这个程序在开局者的浏览器里运行：发身份、收夜里的行动和投票、把查验结果等私下告诉每个人、推进流程，所以**开局者的页面知道所有人的身份**，懂技术的开局者翻自己浏览器的内存就能作弊；这是聚会游戏，不是公证，开局时会提示所有人。身份牌、夜里的行动、选票和法官给每个人的回答都只为一个人加密（两人之间的 ML-KEM 秘密）。夜里每一步，所有活着的人的页面都会各发一条行动消息（有选择的发真的，没有的发空的，时间随机），服务器和其他人看不出谁有神职；能看出的只有“有人在发消息”。白天的发言、上警、骑士决斗和白狼王自爆的结果本来就是公开的。什么都不保存 |
| 游戏「骗子骰」（2.20 起） | 每轮每个页面先发两个 SHA-256 承诺：骰子种子和一个随机数；所有人都发了以后公开随机数，每人的骰子由**自己的种子和所有人的随机数**一起算出，所以谁也挑不了点数，开局的人也看不到别人的骰子。被「开」时公开种子，每个页面自己核对承诺、算出每个人的骰子再数。什么都不保存 |
| 公开桌和大厅（2.20 起） | **公开桌不是私密房间。**它的暗号有固定格式（pub + 玩法 id + - + 16 位随机字符，兼容旧格式 pub + 游戏 + 人数 + 16 位），由开桌的页面生成并交给服务器登记，页面登记时附上房间地址和进入凭证，服务器核对凭证（Node 版另外核对地址确由暗号算出），以后只统计这个房间里有几个人、是不是在玩。首页的大厅把公开桌连同暗号列给任何人，所以**任何人都能进来，服务器也能进来看聊天和牌局**，页面上会明说。私密房间永远不会出现在大厅：服务器只登记格式正确的公开暗号，私密房间的地址也反推不出暗号。大厅只在内存里（Cloudflare 版在一个 Durable Object 里；房间会记下自己是哪张公开桌，好在大厅重启后重新登记，房间空了就删掉），不写盘、不记 IP；防滥用只按数量：每个地址 10 分钟最多开 3 张、全站最多 300 张，没人来的桌子 2 分钟后消失。**公开桌的狼人杀由服务器当法官**（`src/judge.js`，和页面用同一份规则 `dist/werewolf.js`）：服务器发身份、收行动和投票、私下告知查验结果等，所以**服务器知道这局所有人的身份**，没有哪个玩家的页面知道；这些走连接本身（TLS），不走房间的端到端加密。对局只在内存里（Cloudflare 版在房间的存储里，游戏结束或房间空了就删除）。私密房间的狼人杀不变：法官仍是开局者的页面，服务器什么都看不到 |
| 玩法准备与换游戏表决（2.21 起） | 人数可变玩法的「准备」状态、局内换游戏与提前结束本局的提议与表决（≥80% 同意切换），均为端到端加密的游戏事件，经过房间密钥加密与签名，服务器看不懂内容。公开桌换玩法成功后，房间会向服务器发送带新玩法 id 的 table 帧以更新大厅列表，此时服务器会知道该公开桌的新玩法（为了大厅列表正确展示与人数限制）。 |
| 发送确认与送达回执 | 自己的消息先显示“已发出”，表示服务器已转发。2.9 起每个页面每 1.5 秒把自己刚解开的消息（发送者编号 + 序号）列一张单子，用消息密钥封好发给房间，于是“已发出”会变成“已送达 2/3”或“✓ 全部送达”（分母是发送时在场的其他人数）。回执只说明对方的页面收到并解开了，**不代表**对方看过。服务器看不懂也伪造不了回执，但能看出有回执在传（和消息一样只是密文）；房间里的成员能知道谁的页面在线并收到了消息。回执不存储，离开就没了 |
| 图片（2.14 起） | 选好的图片先在**你自己的浏览器里**重新画一遍：缩到能放进一帧（最长边不超过 1600 像素、不超过约 70 KB），文件里除像素以外的东西（EXIF：手机型号、拍摄时间、**GPS 位置**等）全部丢掉。然后用一把新的随机密钥（AES-256-GCM）加密，密文单独发一帧；这把密钥和密文的 SHA-256 放在一条普通消息里，所以同样有签名和前向保密。服务器只转发密文，看不到图片，也拿不到密钥；它能看出“有人发了一张多大的图片”（大小约到 KB）。收到的图片只放在内存里显示，清屏、自动清屏、离开房间后就释放，不写进硬盘或浏览器存储。每人每分钟最多 6 张。别人的屏幕上能截图或另存，这一点网页管不了 |
| HTTP | 用 http:// 打开时浏览器不提供加密功能，页面直接提示无法使用 |

## 服务器端

| | 做法 |
| :--- | :--- |
| Cloudflare 版 | 每个房间一个 Durable Object。成员编号、重连凭证、限速和锁定状态保存在 WebSocket 连接附件里（Cloudflare 平台管理，连接关闭即丢弃），业务代码不写任何存储 |
| Node.js 版 | 房间状态在进程内存里，最后一个连接离开就删除；程序不写日志、不写磁盘（局域网模式只保存自己生成的证书） |
| 防滥用 | 每房最多 25 人；每人可以连发 3 条，之后平均每 6 秒一条；每连接每 10 秒最多 30 个数据帧（其中密钥帧最多 20 个）、4 次心跳；单帧上限约 5.6 KB；连续 5 个格式错误的数据就断开；锁定 / 移出每 2 秒最多一次；同一 IP 每分钟进房次数有上限；Node 版另有总连接上限（`MAX_CONNECTIONS`），接收太慢的连接（积压超过 1 MB）会被断开 |
| 不审查言论 | 没有敏感词过滤、内容审核、举报或封号，也没有给任何人留的后门。服务器拿不到密钥，看不懂消息，也不按内容做任何判断。上面的「防滥用」只看数量、频率和大小，不看内容。房主「移出」是房间里成员之间的事，服务器不参与判断 |
| 来源检查 | 只接受本站网页发起的 WebSocket（Origin 检查）。浏览器以外的程序可以伪造 Origin，所以真正的门槛是进入凭证 |
| 隐身入口 | 自己部署时可设 `ENTRY_PATH`，网站只在秘密路径下打开，其他地址回答普通的 404，扫描者看不出这里跑的是什么。拿到房间链接的人知道路径；监视成员上网的人仍能看到访问了哪个域名 |

## 做不到的事

- **暗号就是一切**。知道暗号的人都能进来、能解密。暗号越短越容易被猜中；拿到房间地址的人（例如服务器运营方）可以离线批量猜测弱暗号，线上限速挡不住这种猜测。重要的谈话用随机暗号。
- **暗号仍然是进门的钥匙**：有了前向保密，事后拿到暗号解不开以前的密文，但拿着暗号的人随时能进来听**以后**的对话；邀请链接不会过期，所有人离开后用它还能开一个新房间。被移出的人也知道暗号，所以要先锁房再移出。
- **前向保密的范围**：发送链每条消息都前进；有人进出、每 100 条或每 10 分钟，发送链和 ECDH 密钥一起换新。页面开着的时候设备被控制，攻击者能读到当时的消息；只偷拷一次密钥的人，在下次换钥后就跟不上了，除非一直控制着设备。签名密钥整个访问期间不变，被偷后在这次访问里能冒充你。勾选「允许旧版本」后，与旧版本之间没有这些保护。这套协议没有经过第三方审计，需要审计过的保证请用 Signal 等成熟工具。
- **进入凭证对服务器可见**：凭证在加密连接里传送，但解开 HTTPS 的一方（服务器、Cloudflare，自己部署时的 Caddy/nginx 等反向代理）都能看到。凭证推不出消息密钥，但拿到它的人可以进房占座、锁房、发无法解密的垃圾消息，也能拿它离线猜暗号（同上一条）。
- **不能证明身份**：知道暗号的人如果和服务器串通，可以夹在两人之间转手消息（给双方看不同的公钥）；通过电话或当面核对 20 位安全码能发现这种调包。安全码只能说明大家看到的是同一组人，说明不了某个编号背后是谁。房主是“最早进来的人”，不代表他就是你想的那个人。
- **服务器能看到元数据**：IP、上线时间、同一房间的连接、消息的长度和节奏、同一暗号的多次使用。要隐藏 IP，请配合可信的 VPN。
- **网页代码由服务器下发**：部署者账号被盗，代码可能被替换成会泄露暗号的版本。能做的核对：网站附带一份用发布密钥签名的文件清单（`/integrity.json`），`node scripts/verify-site.mjs <网址>` 会逐个文件核对哈希，GitHub 上的 `site-watch` 每 6 小时替 chat.freedom8964.com 核对一次。但服务器可以只对特定的人下发改过的代码，外部核对看不到这种针对性的替换；担心这一点就用安卓 App 或离线包，它们的网页随安装包签名发布，不从服务器下载。部署账号务必开启两步验证。
- **设备上的痕迹**：输入法、剪贴板、截图、浏览器历史、系统内存和交换文件都超出网页能控制的范围。`Clear-Site-Data` 是否生效取决于浏览器；释放引用也不能强制擦除内存。
- **对方可以保存**：截图、拍照、复制都挡不住。
