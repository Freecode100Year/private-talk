# 隐私与安全设计

[README](../README.md) 里是简要版。这里逐项写清楚每一层怎么做、能防什么、防不了什么。适用于 2.0 及以后的版本。

## 一句话

无需账号；消息在浏览器里加密；本项目的转发程序不保存聊天消息、不写日志。**但**服务器能看到连接信息，参与者能自行保存内容，网页代码和设备本身仍需要可信。

## 谁能看到什么

| | 服务器运营方 | 网络上的旁观者（运营商、Wi-Fi 管理者） | 房间里的其他人 |
| :--- | :--- | :--- | :--- |
| 消息内容 | 看不到（只有密文） | 看不到（HTTPS + 端对端加密） | 看得到，也能截图、复制 |
| 暗号 | 看不到（只在浏览器里用） | 看不到 | 知道 |
| 你是谁 | 不知道（无账号、无昵称） | 不知道 | 只看到编号 1️⃣～🔟 |
| 你的 IP 和上线时间 | 看得到 | 看得到你连了这个网站 | 看不到 |
| 哪些连接在同一个房间、消息的长度和时间 | 看得到 | 看不到 | 看得到 |
| 同一个暗号以后又被打开 | 看得到（房间地址相同） | 看不到 | — |

## 密钥与房间

| | 做法 |
| :--- | :--- |
| 暗号 | 默认随机生成 22 个字符（约 128 位随机性）。放在链接 `#` 后面，浏览器不会把它发给服务器；进入房间后立即从地址栏抹掉；页面只显示 4 位房间代号，截图不会泄露暗号 |
| 派生 | 暗号经 PBKDF2-SHA256（31 万次）得到主密钥，再用 HKDF 分出两样互不相关的东西：**进入凭证**和**消息密钥** |
| 房间地址 | 进入凭证的 SHA-256。服务器知道地址，但由地址算不出进入凭证，更算不出暗号和消息密钥 |
| 进入 | 连接时浏览器出示进入凭证（放在 WebSocket 子协议头里，不在网址里），服务器核对它的 SHA-256 等于房间地址才放行。**只知道房间地址的人（例如从日志里看到）进不来**：不能占座、不能锁房、不能发消息 |
| 消息 | AES-256-GCM，每条消息随机 12 字节 IV。消息密钥从不离开浏览器，服务器只转发密文 |
| 长度 | 加密前把每条消息补齐到 256 / 512 / 1024 / 2048 / 4096 字节中最近的一档（ISO/IEC 7816-4 填充），服务器和网络旁观者只能看出大概档位，看不出一句话多长 |
| 防篡改 | 发送人编号、消息编号、发送时间都封在密文里。浏览器核对服务器标注的发送人，拒绝本页已见过的消息编号，并**按本机时间**拒绝相差 10 分钟以上的消息（服务器报的时间只用来提醒本机时间不准，不参与判断） |
| 房间代号 | 4 位十六进制，约 16 位，只用来发现暗号输错，**不是安全验证码** |

## 房间与成员

| | 做法 |
| :--- | :--- |
| 身份 | 无账号、无昵称，按进入顺序编号 1️⃣～🔟。先发没用过的编号，10 个都用过后再发最早空出的那个。编号只是座位号，不能证明对方是谁 |
| 房主 | 连续在房间里最久的人是房主（👑），由服务器按进入顺序判定。**只有房主**能锁定 / 解锁、移出成员；房主离开或掉线后，下一位最早进入的人自动接任；掉线回来的人排到最后 |
| 锁定 | 锁定后新的人进不来；掉线的人凭重连凭证 2 分钟内能回来 |
| 移出 | 房主移出某人：服务器断开他，并作废他的重连凭证。房间锁定时他回不来；没锁时他拿着链接仍能作为新成员进来，所以要先锁再移出 |
| 断线 | 每 25 秒心跳，无响应或断开就自动重连；掉线 2 分钟内凭重连凭证回来仍是原编号。**所有人都断开时**（例如大家同时锁屏），房间状态（编号、锁定、重连凭证）随之消失，再连上就是重新开始的房间，页面会提示编号已变、锁定已解除 |
| 历史 | 不存储。新加入的人看不到之前的消息；断线期间的消息收不到 |

## 网页与浏览器

| | 做法 |
| :--- | :--- |
| 网页 | 无外部资源、无统计、无 Cookie；CSP 只允许本站资源；不发送 Referer；禁止被其他网站嵌入；HSTS |
| 本地痕迹 | 不用 Cookie、localStorage 等浏览器存储；所有响应 `Cache-Control: no-store`；打开、切到后台、关闭页面时请求 `/bye`，服务器回 `Clear-Site-Data: "cache", "storage"`；`NEL: {"max_age":0}` 关闭网络错误上报；离开时丢掉暗号、密钥和消息的引用；输入框关闭拼写检查 |
| 清屏 | 「清屏」和「本机自动清屏」只清**你自己这台设备**的屏幕，不影响别人，也删不掉别人保存的内容 |
| 发送确认 | 自己的消息显示“已发出”表示服务器已转发，**不是**对方已读或已收到 |
| HTTP | 用 http:// 打开时浏览器不提供加密功能，页面直接提示无法使用 |

## 服务器端

| | 做法 |
| :--- | :--- |
| Cloudflare 版 | 每个房间一个 Durable Object。成员编号、重连凭证、限速和锁定状态保存在 WebSocket 连接附件里（Cloudflare 平台管理，连接关闭即丢弃），业务代码不写任何存储 |
| Node.js 版 | 房间状态在进程内存里，最后一个连接离开就删除；程序不写日志、不写磁盘（局域网模式只保存自己生成的证书） |
| 防滥用 | 每房最多 10 人；每人每 6 秒一条；每连接每 10 秒最多 20 个数据帧、4 次心跳；单帧上限约 5.6 KB；连续 5 个格式错误的数据就断开；锁定 / 移出每 2 秒最多一次；同一 IP 每分钟进房次数有上限；Node 版另有总连接上限（`MAX_CONNECTIONS`），接收太慢的连接（积压超过 1 MB）会被断开 |
| 不审查言论 | 没有敏感词过滤、内容审核、举报或封号，也没有给任何人留的后门。服务器拿不到密钥，看不懂消息，也不按内容做任何判断。上面的「防滥用」只看数量、频率和大小，不看内容。房主「移出」是房间里成员之间的事，服务器不参与判断 |
| 来源检查 | 只接受本站网页发起的 WebSocket（Origin 检查）。浏览器以外的程序可以伪造 Origin，所以真正的门槛是进入凭证 |

## 做不到的事

- **暗号就是一切**。知道暗号的人都能进来、能解密。暗号越短越容易被猜中；拿到房间地址的人（例如服务器运营方）可以离线批量猜测弱暗号，线上限速挡不住这种猜测。重要的谈话用随机暗号。
- **同一个暗号永远对应同一把钥匙**：以后得到暗号的人，能解开以前被截获的密文（没有前向保密）；有人离开后钥匙不会更换；邀请链接不会过期，所有人离开后用它还能开一个新房间。需要这些保证要换用经过公开安全审计的协议（如 MLS），目前没有做。
- **进入凭证对服务器可见**：凭证在加密连接里传送，但解开 HTTPS 的一方（服务器、Cloudflare，自己部署时的 Caddy/nginx 等反向代理）都能看到。凭证推不出消息密钥，但拿到它的人可以进房占座、锁房、发无法解密的垃圾消息，也能拿它离线猜暗号（同上一条）。
- **不能证明身份**：所有成员共用一把钥匙，知道暗号的成员如果和服务器串通，可以冒充别人；房主是“最早进来的人”，不代表他就是你想的那个人。
- **服务器能看到元数据**：IP、上线时间、同一房间的连接、消息的长度和节奏、同一暗号的多次使用。要隐藏 IP，请配合可信的 VPN。
- **网页代码由服务器下发**：部署者账号被盗，代码可能被替换成会泄露暗号的版本。部署账号务必开启两步验证；需要更高保证时，应自己部署并核对代码。
- **设备上的痕迹**：输入法、剪贴板、截图、浏览器历史、系统内存和交换文件都超出网页能控制的范围。`Clear-Site-Data` 是否生效取决于浏览器；释放引用也不能强制擦除内存。
- **对方可以保存**：截图、拍照、复制都挡不住。

## 版本说明

2.0 改了密钥派生和连接协议（新增进入凭证、房主），与 1.x 不兼容：同一个暗号在 2.0 网站上对应新的房间地址。网页每次都从服务器加载最新版本，所以使用者无需任何操作；自己部署 Node.js / Docker 版的，网页和服务器在同一个包里，一起升级即可。
