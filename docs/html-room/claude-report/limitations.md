# HTML Room 已知限制（V1）

## 安全

1. **无口令文件就是钥匙。** 经手文件的任何系统都能进入房间、读到之后的消息。见 [security-model.md §3](security-model.md#3-文件即钥匙)。
2. **口令文件可被离线穷举。** 强度只取决于口令；短 PIN 不能防平台。生成器要求至少 8 个字符并提供 12 位随机口令。
3. **邀请不过期，无法吊销。** 只能新建房间。
4. **网页模式与浏览器内生成器信任网站当时的代码。** 不等同于经过核对的离线文件。
5. **成员身份不是真实身份。** 编号 + 本次访问的签名密钥；送达确认不能证明来自独立设备。核对安全码是唯一的防调包手段。
6. **中继掌握元数据**：IP、时间、Room ID、房间人数、帧大小档位。隐藏 IP 需配合可信 VPN。
7. **meta CSP 的限制**：`frame-ancestors`、`sandbox`、`report-uri` 无效。
8. **消息时间窗按本机时钟**（±10 分钟），时钟严重不准的设备会拒收消息（页面会提示偏差）。
9. **ML-KEM 实现未经独立审计**，与 ECDH 混合使用，不单独依赖（沿用 v3.2 的设计）。

## 功能

10. V1 只有文字聊天：没有图片、游戏，中继对 `/hr/` 丢弃这些帧。
11. 没有房主锁房 / 移出成员的界面（中继支持，页面只显示相关通知）。
12. 不保存任何内容：刷新或关闭即丢失，刷新后是新成员。
13. 没有昵称，只显示编号。
14. 每个房间最多 25 人（与原有房间相同的中继上限）。
15. 一个文件最多 4 个中继，按顺序切换，不做并行连接。
16. 模板随客户端代码变化而变化：旧文件中的客户端不会自动更新；`hashes.json` 只记录当前版本的哈希。核对旧文件需要对应版本的仓库。

## 验证

17. 只在 Linux 上的无头 Chromium 153 中做了真实浏览器测试。Firefox、Safari、Windows/macOS 桌面浏览器、Android、iOS、微信、QQ 均**未验证**，见 [compatibility.md](compatibility.md)。
18. Worker 只在本地 workerd（`wrangler dev`）中测试，**未部署到生产环境**。
19. 自签名证书中继的提示只在逻辑上实现，未在真实浏览器中走通“信任证书后重连”的流程。
