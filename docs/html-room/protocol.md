# HTML Room V1 frozen protocol

Master: CSPRNG 32 bytes. HKDF-SHA-256 salt = 32 zero bytes, info = UTF-8 `private-talk/html-room/v1/access`, `/key`, `/bind` (full prefix for each), output = 32 bytes each. No integers or byte-order conversions. Master and binary fields use canonical lowercase hex in config. access header = `pt2, a<access hex>`; optional resume is memory-only. roomId = lowercase hex SHA-256 of raw access bytes. Byte-level public test vector: hkdf-vector.json (00..1f is a published vector, never a production room).

Announcement key: AES-256-GCM imported from key output. Random 12-byte IV, AAD UTF-8 `private-talk/html-room/v1/keys|<roomId>`, pad/unpad from existing crypto.js. Only announcements use this key. Validate kind, from, random 8-byte ID, +/-10-minute timestamp, duplicate ID, v32 and signature. Reject identity changes until a new session. Existing Group v3.2 is reused unchanged. Ordinary text and kind=seen receipts use Group.seal/open and require verified signatures and hybrid readiness. Receipt l entries identify [sender, chain-header]. Relay echo means submitted, never receiver confirmation.

Dedicated /hr/<roomId> permits pt2 authentication before room admission, Origin exactly null or relay same origin, distinct hr namespace, only ping/key/msg/seen accepted. seen carries v3 h. table/lobby/ref/file/lock/remove discarded. Old /ws null Origin remains forbidden. Access is a replayable bearer; stolen access permits admission and resource abuse, but does not derive E2EE keys. Message chain counters and bounded announcement age/ID cache prevent ordinary replay within session; malicious relay can withhold traffic and lie about membership. New session keys prevent old wraps from decrypting.

Config is non-executable application/json, escape < > / U+2028 U+2029. Schema version 1; relay whitelist validates exact ws(s) origin before generation (ws allowed only localhost/127.0.0.1/[::1] tests). Secret mode includes master. Wrapped mode includes encrypted=true, salt (16 bytes), iv (12), ciphertext (48), kdf={name:PBKDF2,hash:SHA-256,iterations:310000}, version and relay/roomId only. PBKDF2 uses UTF-8 password without normalization and AES-256-GCM wrapping with AAD UTF-8 `private-talk/html-room/v1/wrap|<roomId>`. Reject other KDF parameters before work. UI password maximum 1024 UTF-8 bytes; one in-flight unlock, local increasing delay. No connection before unlock and roomId verification.

## Claude 整合裁定

本分支只保留上文 canonical 配置 `{version,relay,roomId,encrypted,...}` 和 310000 轮 PBKDF2，不接入第二套 600000 轮、NFC 口令或 v/name/relays/secret/lock 文件格式。原 Claude 文件请重新生成。新 `#hr1=` 为 UTF-8 canonical JSON 的无 padding base64url，最大编码 8192 字符、解码 4096 字节；拒绝坏编码/未知字段/不合法配置。Hosted entry 只连接与当前网页同源对应的 WS/WSS 源，解锁前不连接，读取后清除 fragment。生成器明确提交的中继源构成一项白名单，模板脚本及样式哈希必须与固定构建值一致。浏览器填充与 CLI render 字节一致。全部聊天和 seen 仍走 Group 签名链，不使用共享 AEAD 做回执。
